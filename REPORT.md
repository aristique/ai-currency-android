# Отчёт по лабораторной №4

## Тема
Мобильный конвертер официальных курсов BNM с аналитикой валютной пары за 7 и 30 дней. Выбран предусмотренный методичкой вариант Б — развитие темы конвертера.

## Смена языка
№3: Python и браузерный JavaScript. №4: Kotlin, нативные Android Views и собственный Canvas-график. Код Python/JavaScript не копировался и автоматически не переводился; мобильная логика написана заново по требованиям. Domain, Repository, MainActivity и ChartView имеют отдельную архитектуру.

## Исторические данные
История получается из официального XML BNM отдельными запросами по календарным датам. Первый месячный экран может потребовать до 30 запросов; данные сохраняются в файлах внутри приложения и читаются при повторном запуске. Корректные ответы выходных дней используются как опубликованы. Пропуски не заменяются выдуманными значениями; полнота периода и дата последних данных показаны явно. Нет гарантии доступности BNM: при сетевом сбое оставшаяся история читается из кэша, а повторная загрузка позволяет получить недостающие дни.

## IDE, ИИ и сборка
Все работы выполнены Codex по явному решению пользователя. Точное имя модели этой сессии не фиксировалось. Copilot и Antigravity не использовались. Применены Kotlin 2.1.21, Android Gradle Plugin 8.9.2, Gradle 8.11.1, JDK 21 с целевым байткодом 17, Android SDK 35. Инструменты сборки находятся в Docker. SDK command-line tools загружены с Google и проверены по опубликованному SHA-256.

## Результаты ИИ и ошибки
С первой компиляции Kotlin-код конвертера, трёх экранов и графика собрался в настоящий debug APK.
Первая попытка запуска Gradle остановилась до компиляции: рабочая папка /project принадлежала root и была недоступна пользователю gradle. Исправлены владелец папки и каталог постоянного debug-ключа.
В сетевом чтении заменён readNBytes, не подходящий для минимального Android API, на ограниченное чтение буфера. Добавлена проверка размера ответа.
Android Lint обнаружил атрибут светлой панели навигации, требующий API 27 при заявленном минимуме 26. Атрибут удалён, минимальная версия Android сохранена.
Пользователь вручную исходники не редактировал; исправления выполнял Codex. Запуск на устройстве ещё не подтверждён, поэтому отчёт не выдаёт успешную сборку за живую демонстрацию.

## Работа с ИИ на новом языке
В Python короткий цикл проверки упрощается стандартной библиотекой и небольшим контейнером. В Kotlin статические типы и компилятор помогают заранее обнаруживать несоответствия, но одновременно нужно учитывать Android API, жизненный цикл Activity, выполнение сети вне главного потока и совместимость Gradle/JDK/SDK.
На практике больше времени заняла подготовка мобильной сборки и её окружения, чем перенос математических требований. Саму логику не переносили из исходников: BigDecimal, разбор XML, файловый кэш и статистика реализованы независимо на Kotlin. Это показывает, что с ИИ можно работать на другом языке, но результат всё равно требует проверки платформенных ограничений и поведения на устройстве.
